*For the customer's engineer and their platform team.*

Seven steps deploy this project, five CI checks gate it, and **two** IAM documents govern it —
one per principal, and merging them is the mistake to avoid. Summarised from the committed runbook
at `deploy/deploy.md`, the gate at `deploy/ci.sh`, and the policies at `deploy/iam_policy.json`.
Verified against `@aws/agentcore` 1.0.0-preview.22. Read
[AgentCore CLI](/docs/platform/agentcore-cli) first if you have not: the two dead commands are why
this runbook exists.

## Path

<Steps>

<Step>
**Install the toolchain, remove the colliding binary, install the CDK deps.**

```bash
npm install -g @aws/agentcore
agentcore --version                                  # 1.0.0-preview.22
pip uninstall -y bedrock-agentcore-starter-toolkit   # not optional — see the CLI page
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
(cd agentcore/cdk && npm install)                    # MANDATORY
```
</Step>

<Step>
**Author the deployment target.** `agentcore/aws-targets.json` ships as `[]`; region and account
come from **that file only**, and `deploy` has no `--region`/`--profile`/`--agent`.

```bash
export AWS_REGION=us-east-1            # explicitly. AWS_DEFAULT_REGION is IGNORED
export AWS_PROFILE=your-bedrock-profile
```
</Step>

<Step>
**Enable Bedrock model access in that region — for the `global.*` prefix.**

Configuration targets `global.*` inference profiles because `us.*` costs exactly **1.10×** on
every rate category. A policy allowing only `us.anthropic.*` **silently forbids the cheaper
prefix**, and presents as an access-denied error rather than as a cost decision. See
[Cost levers](/docs/cost/levers).
</Step>

<Step>
**Run the gate.**

```bash
bash deploy/ci.sh
```
</Step>

<Step>
**Deploy.**

```bash
agentcore deploy --target default --yes
# --verbose for resource-level CloudFormation events; --json for machine-readable output
```

Order of operations: resolve the target → validate the project spec → `npm run build` in
`agentcore/cdk/` → **create credential providers out of band** → synthesize CloudFormation →
bootstrap the environment if needed (**only with `--yes`**; otherwise it stops and tells you) →
check stack deployability → deploy stack `AgentCore-ppFraud-default` → persist deployed state →
enable Transaction Search.

Exit **2 means deployed with post-deploy warnings — a pass.** `ci.sh` treats it as one.
</Step>

<Step>
**Invoke.**

```bash
agentcore invoke --runtime underwriter --target default --stream \
  "Run a full underwriting review of APP-1004"

SESSION_ID="$(python3 -c 'import uuid; print(uuid.uuid4())')"   # 36 chars, not .hex's 32
agentcore invoke --runtime francis --session-id "$SESSION_ID" --user-id analyst-42 "…"
```

`--user-id` becomes the memory `actorId`, so it must be stable per analyst for long-term memory to
accumulate against the right namespace.
</Step>

</Steps>

## CI gate

`deploy/ci.sh` is non-interactive and **creates no AWS resources**.

| # | Step | Needs AWS? |
|---|---|---|
| 0 | **Dead-command guard** — fail if `agentcore configure` / `agentcore launch` appear anywhere in tracked-or-untracked-not-ignored files; fail if the pip starter toolkit is installed | no |
| 1 | `agentcore validate --json` — Zod-validate `agentcore/*.json`, root spec is `.strict()` | no |
| 2 | `pytest -q --ignore=agentcore` | no |
| 3 | `agentcore package` — build each runtime's CodeZip closure | no AWS, but hits PyPI |
| 4 | `agentcore deploy --dry-run --target <target> --json` | **read-only** credentials |

Step 4 skips automatically while `aws-targets.json` is still `[]` — a dry run could then only fail
with `Target "default" not found`, which is not a code defect — or on `CI_SKIP_DRY_RUN=1`. It also
asserts the region is explicit:

```bash
: "${AWS_REGION:?AWS_REGION must be set explicitly before a dry-run deploy}"
```

Three details in that script exist because of a real failure, and are worth not "simplifying":

- **`--ignore=agentcore`** on pytest. A previous `agentcore package` leaves
  `agentcore/<runtime>/staging/`, the full dependency closure, and several third-party wheels there
  ship test modules with colliding basenames (two copies of `annotated_types/test_cases.py`). Bare
  `pytest` aborts during collection with `import file mismatch` **before reaching a single project
  test**.
- **Exit code 2 treated as success.** Otherwise the gate fails a successful deploy.
- **Four exemptions to the dead-command guard** — `deploy/ci.sh`, `deploy/deploy.md`,
  `evals/README.md`, `tests/test_bench.py` — the files whose *purpose* is to warn about the
  commands. `tests/test_bench.py` additionally asserts the warning is present and is not inside a
  runnable code block.

## IAM: two documents, two principals

`deploy/iam_policy.json` holds two policy documents with `_purpose` annotations on every statement.
IAM ignores unknown keys, but some tooling rejects them, so strip them on the way in:

```bash
ACCOUNT_ID=123456789012

jq --arg a "$ACCOUNT_ID" '
  .deployingPrincipal
  | {Version, Statement: [.Statement[] | del(._purpose)]}
  | walk(if type == "string" then gsub("<ACCOUNT_ID>"; $a) else . end)
' deploy/iam_policy.json > /tmp/deployer.json

aws iam put-role-policy --role-name <your-deploy-role> \
  --policy-name AgentCorePpFraudDeploy \
  --policy-document file:///tmp/deployer.json
```

| | `runtimeExecutionRole` | `deployingPrincipal` | Recommendation |
|---|---|---|---|
| Assumed by | `bedrock-agentcore.amazonaws.com` | a human or CI identity | keep separate |
| Creates infrastructure? | **No** | Yes — CDK CloudFormation deploy | keep separate |
| Deletes resources? | No | **Yes**, because a rename is Delete+Create | keep separate |
| Calls models? | Yes: `bedrock:`, plus `bedrock-mantle:CreateInference` | No | keep separate |
| Blast radius if leaked | one runtime's model and memory access | the whole stack | **do not merge them** |

<Tabs items={['runtimeExecutionRole', 'deployingPrincipal']}>
<Tab value="runtimeExecutionRole">

What the `underwriter` and `francis` containers run as. `agentcore deploy` synthesizes one
execution role per runtime via CDK; attach this document to those roles, or supply a pre-made role
per runtime through `agentcore.json`'s `executionRoleArn`. Trust policy is
`bedrock-agentcore.amazonaws.com` with `aws:SourceAccount` / `aws:SourceArn` conditions, which CDK
writes for you.

| Statement | What it is for |
|---|---|
| `InvokeClaudeFoundationModels` | On-demand model invocation. Kept **alongside** the profile statement because an inference profile fans out to the underlying foundation-model ARN in each member region, and that ARN must also be allowed. |
| `InvokeClaudeInferenceProfiles` | Both `global.*` **and** `us.*`. `global.*` MUST be listed — a policy allowing only `us.anthropic.*` silently forbids the cheapest profile. |
| `InferenceProfileDiscovery` | Resolve a profile to its member regions and let a healthcheck assert the model is `ACTIVE` before serving traffic. Read-only; these actions are not resource-scopable. |
| `AgentCoreMemoryDataPlane` / `AgentCoreMemoryDescribe` | Francis's session manager. Both AgentCore planes sign as `bedrock-agentcore`, so the **resource scope** is what separates control from data. |
| `AgentCoreWorkloadIdentity` | The runtime exchanges its execution identity for a workload access token before fetching any outbound credential. Required as soon as a credential provider exists. |
| `AgentCoreOutboundCredentials` + `ReadCredentialProviderSecret` | Fetch the Snowflake PAT / OAuth token through the provider instead of baking a secret into the image. AgentCore Identity keeps the material in a Secrets Manager secret under the `bedrock-agentcore-identity!` prefix — **without `GetSecretValue` on that prefix the token fetch fails.** |
| `InvokeSemanticLayerGateway` | SigV4-signed outbound call to the Gateway fronting the signal layer. Only needed once `agentCoreGateways` is non-empty. See [Semantic layer question](/docs/platform/semantic-layer). |
| `RuntimeLogs` | Its own log group. Runtime — **and only Runtime** — gets its log destination wired automatically; the role still needs write access. |
| `SpanAndTraceExport` + `WriteSpansToLogs` | `aws-opentelemetry-distro`'s exporters, plus the Transaction Search destination. Neither X-Ray write action supports resource-level scoping. |
| `PerAgentSpendMetrics` | Namespace-scoped `cloudwatch:PutMetricData`. Needed because **the AgentCore SDK publishes no token or cost span attributes and Strands records its token histograms without attributes** — per-agent spend telemetry is this repo's own code. |

`bedrock-mantle` is a separate prefix. Synthesis runs on GPT-5.6 Luna, which needs
`bedrock-mantle:CreateInference` (managed policy `AmazonBedrockMantleInferenceAccess`), not covered
by any `bedrock:*` grant. See [GPT-5.6 on bedrock-mantle](/docs/platform/bedrock-mantle).

</Tab>
<Tab value="deployingPrincipal">

The identity that runs `agentcore deploy`. Deploy is a CDK CloudFormation deploy: it synthesizes
IAM roles, stages assets in the bootstrap bucket, runs an out-of-band identity pre-step, and on a
first deploy with `--yes` bootstraps the environment.

| Statement | Note |
|---|---|
| `CloudFormationStackLifecycle` | Change-sets stack `AgentCore-ppFraud-<target>`, and reads stack status first to decide deployability. |
| `CdkBootstrapAssetBucket` | CDK stages both CodeZip bundles and the template as assets **before** CloudFormation reads them. |
| `CdkBootstrapSsmVersion` | CDK reads `/cdk-bootstrap/<qualifier>/version` to decide whether the environment is bootstrapped; `--yes` auto-bootstraps, which writes it. |
| `CdkBootstrapRoleAssumption` | CDK's default synthesizer **assumes** the bootstrap deploy / file-publishing / lookup / cfn-exec roles rather than acting as the caller. Omit it and deploy fails at asset publish with a misleading "needs bootstrapping" message. |
| `SynthesizeExecutionRoles` | The one statement that **cannot be avoided** for a multi-runtime project — the stack creates one execution role per runtime plus inline policies. Name-prefix-scoped, not `*`. |
| `PassExecutionRoleToAgentCore` | `CreateAgentRuntime` hands the role to the service, so `iam:PassRole` is required. Condition-locked to that one service. |
| `AgentCoreControlPlane` | Create/update/**delete** the runtimes, endpoints and memory. Delete actions are there because [renaming a resource is Delete+Create](/docs/platform/agentcore-cli#renaming-a-resource-destroys-it). |
| `AgentCoreCredentialProviders` | The out-of-band identity pre-step. **This is why `agentcore/.cli/deployed-state.json` must be committed** — the provider ARNs are recorded only there. |
| `CreateCredentialProviderSecret` | Only needed once `credentials[]` is non-empty. |
| `ObservabilityDeliveryWiring` | Memory and Gateway receive **no** log or trace destination automatically. Skip this and `francisMemory` is silently trace-free. |
| `EnableTransactionSearchOnce` | The account-level setup below. |
| `InvokeDeployedRuntime` / `ReadLogsAndTraces` / `SpendDashboard` / `CallerIdentity` | `invoke`, `logs`, `traces`, `status`, the dashboard, and the pre-flight account check deploy makes against `aws-targets.json`. |

</Tab>
</Tabs>

Both documents keep `region: *` so one policy covers a us-east-1 and a us-west-2 target. Narrow it
once the customer settles on a single region.

## One-time: CloudWatch Transaction Search [#one-time-cloudwatch-transaction-search]

Skip this and you get AgentCore service metrics and **zero spans** — no per-agent latency and no
token attribution to look at, which is precisely what this engagement needs to show.

`agentcore deploy` attempts it whenever the project has a Python runtime, as both of these do, and
reports that transaction search is enabled and takes roughly 10 minutes to become fully active and
index traces from invocations. It makes four idempotent account-level calls, which is exactly what
the `EnableTransactionSearchOnce` statement grants:

1. `application-signals:StartDiscovery`
2. a CloudWatch Logs resource policy named **`TransactionSearchXRayAccess`** granting
   `logs:PutLogEvents` to principal `xray.amazonaws.com` on log groups `aws/spans` and
   `/aws/application-signals/data`, conditioned on `aws:SourceAccount` and an `aws:SourceArn`
   `ArnLike` of `arn:aws:xray:<region>:<account>:*`
3. `xray:UpdateTraceSegmentDestination` → `CloudWatchLogs`
4. `xray:UpdateIndexingRule` — rule `Default`, probabilistic, 100% sampling

If the customer will not grant those actions to the deploy role, have an admin run the equivalent
once and then stop the CLI trying:

```bash
agentcore config disableTransactionSearch true
# or keep it on and sample less:
agentcore config transactionSearchIndexPercentage 10
```

An empty `agentcore traces list` right after the first deploy is expected rather than a bug — the
~10 minute indexing delay is real.

## Operating

```bash
agentcore status --json                          # all resources and their state
agentcore logs   --runtime underwriter --since 30m --level error
agentcore logs   --runtime francis --query "ConcurrencyException" --json
agentcore traces list --runtime underwriter --limit 20 --since 1h
agentcore traces get <traceId>                   # downloads to a JSON file
agentcore exec   --runtime underwriter --it      # shell into a running container
```

## Local development

```bash
agentcore dev --runtime underwriter --logs
agentcore dev --runtime francis --logs           # index 1 → port 8081
```

- `--runtime` is **required in non-interactive mode** with more than one runtime.
- The local server exposes `POST /invocations` and `GET /ping`, and — like the deployed runtime —
  replies `text/event-stream` **always**.
- **Memory is not available under `agentcore dev`.** The Francis session manager no-ops when
  `MEMORY_FRANCISMEMORY_ID` is unset, so local runs are stateless by design.
- Local-dev identity writes `.agentcore.json` into the **current working directory**. It is
  gitignored; do not commit it.

## Production hardening still open [#production-hardening-still-open]

Six gaps between this demo and production, in the order they should be closed.

| Gap | What closing it takes | Blast radius if skipped |
|---|---|---|
| **Data layer** | Replace the fixture backend with the Lambda Gateway target fronting Snowflake or Aurora. Nothing above the signal layer changes. [Semantic layer question](/docs/platform/semantic-layer) | the demo reads fixtures, not the customer's data |
| **Guardrails** | Attach a Bedrock Guardrail so SSN redaction is enforced *server-side*. General Rule 23 is enforced in the signal layer today, which is the right place but should not be the only one. [General Rules coverage](/docs/fidelity/general-rules) | one code path is the sole barrier to a raw SSN in a prompt |
| **Identity** | `authorizerType: CUSTOM_JWT` on the endpoints, with an `authorizerConfiguration.customJwtAuthorizer` block. Validate rejects either without the other, in both directions | calls are not attributable per underwriter |
| **In-platform evaluation** | `agentcore add evaluator` / `add dataset` / `run eval` / `add online-eval`. The evaluator configs and golden dataset are written and schema-validated but not registered against a deployed runtime. [Eval harness](/docs/reference/eval-harness) | no continuous calibration check |
| **Model pinning** | Pin model ids to an exact version. Two current ids (`claude-sonnet-5`, `claude-opus-5`) carry no date suffix | adjudications are not reproducible across a model refresh |
| **Throughput** | A concurrency benchmark. Nothing measured says what happens to p95 or the throttle rate when adjudications overlap | unknown behaviour under real load |

## Still unknown

**No `agentcore deploy` has run against a live account from this repository.** Steps 1 through 4 of
the CI gate pass; step 5's dry run is skipped because `aws-targets.json` is still `[]`. The one
`server_5xx` pair observed at concurrency 1 is a reason to expect the throughput row above to
matter, not evidence about what it will show.
