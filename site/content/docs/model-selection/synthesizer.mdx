## What the synthesizer is

The master adjudicator. It receives **all eight specialist narratives** substituted into the
customer's verbatim `master_agent_prompt.txt` and emits the **21-key adjudication object**. On
a real application that prompt is **31,343 characters** — measured on APP-1004, with the eight
narratives in place — and the reply is ~800–1,000 tokens of JSON.

It is therefore the single largest call in the pipeline, and it is serial: nothing can start
until all eight specialists have finished.

## The measurement that decided it

Measured on APP-1004, against **the same eight analyses**, **n=1 each**:

| Synthesizer | Wall clock | Cost | Result |
|---|---:|---:|---|
| Claude Sonnet 5 | **55.2 s** | $0.11731 | 21/21 keys, HIGH RISK / DECLINE |
| GPT-5.6 Luna | **6.1 s** | $0.01488 | 21/21 keys, HIGH RISK / DECLINE |

Identical verdict, ~9x faster, ~87% cheaper on that call. The Claude synthesis alone consumed
**55.2 s of a 101.1 s end-to-end run** (28,567 input tokens for 6,018 output tokens); the
substitution took that measured end-to-end to **37.5 s**.

<Callout type="warn" title="n=1, and the page says so">
This is one application, one call each. It is enough to separate 55.2 s from 6.1 s — a 9x gap
is not a sampling artifact — and it is **not** a distribution. `agents/mantle.py` records a
slightly different pair for the same substitution measured on a different draw (55.2 s /
$0.11731 against **4.4 s / $0.01314**), which is exactly the run-to-run spread you would expect
at n=1. Neither number is a benchmark; the 42-run figure below is.
</Callout>

### The token profile, and why it looks strange

| Token class | Total over 42 calls | Mean per call |
|---|---:|---:|
| Input | 84 | **2.0** |
| Output | 30,066 | 715.9 |
| Cache read | 0 | 0.0 |
| **Cache write** | **180,610** | **4,300.2** |

Two input tokens per call. The entire ~31K-character prompt lands in the **cache-write** class,
because implicit caching is on by default for GPT-5.6 and every application's prompt is new.

<Callout type="error" title="This is why the cache-write term is load-bearing">
GPT-5.6 bills cache-write at **1.25x the uncached input rate**. Omitting that term
under-reported a measured Luna call by **62%** — `cacheWriteInputTokens=6740` was **$0.00927 of
a $0.01499 call**. `agents/mantle.py:CACHE_WRITE_MULTIPLIER` prices it, and GPT-5.4/5.5 carry a
multiplier of **0.0** because they cache automatically with no write charge.
[Cost levers](/docs/cost/levers#gpt-56-cache-write-tokens-bill-at-125x-input).
</Callout>

Note also that `agents/mantle.py:_usage` normalises the Responses convention onto the Bedrock
Converse one. Responses `usage.input_tokens` is the **total** prompt size and already includes
cached tokens; Converse reports only the non-cached count. Subtracting keeps a cached token
billed once, at the right rate, for both families — otherwise `agents/pricing.py` would
double-count.

## The 21-key contract is validated, not assumed

The synthesizer's whole job is a contract, so the routing validates rather than trusts:

- `structured_output_model=Adjudication` on the Converse path — Strands converts the pydantic
  model to a forced tool spec and hands the model back its own validation errors mid-loop.
- On the mantle path there is no equivalent tool, so `agents/synthesize.py:_invoke_master_mantle`
  parses the reply and validates it against the same `Adjudication` model, feeding the same
  bounded-repair loop. Exactly **one** repair invocation is allowed; after that it **raises**.
- **There is no code path that emits an unvalidated adjudication.**

Measured over the 42 runs: **42 of 42 validated**, including the one degraded run that lost two
specialists to `InternalServerException`. **0 repairs needed.**

`agents/models.py:SYNTHESIZER_MAX_TOKENS` is 4096, and the reason is in its comment: the
customer caps each of nine summaries at "under 1200 characters", which is ~2,850 tokens plus
JSON scaffolding. Measured, the largest synthesis wrote **1,005** output tokens and the median
**666** — so 4096 is 4.1x the observed ceiling and has never bound.

<Callout type="warn" title="Truncation here destroys the object rather than shortening it">
A truncated synthesis fails the 21-key contract outright — a *failed* adjudication, not a
cheaper one. And the ceiling does matter in the other direction: an earlier pass measured that
at `max_tokens=16384` a live synthesis took **84 s of a 113 s end-to-end run** and emitted
**9,244** output tokens, far past the contract it was asked to honour.
</Callout>

## Which variant, and it is not the ordering anyone expects

Measured on the real 31,343-character prompt, streamed Responses calls, `effort=low`, **n=3 per
cell**, 2026-07-28. All 24 calls returned a valid 21-key `Adjudication` and all 24 adjudicated
**HIGH RISK / DECLINE** — so the latency spread is not bought with a shorter or worse answer.

| Variant | Best measured p50 | Input / cache-read / output per 1M |
|---|---:|---|
| **GPT-5.6 Luna** | **4.61 s** (us-east-1) | **$1.10 / $0.11 / $6.60** |
| GPT-5.6 Terra | 6.29 s (us-east-2) | $2.75 / $0.28 / $16.50 |
| GPT-5.6 Sol | 11.19 s (us-east-1) | $5.50 / $0.55 / $33.00 |

**5x the token price buys 2.4x more latency on this workload.** There is no speed-for-money
trade to make, and Luna is not a compromise pick — it is both the cheapest and the fastest.

Full matrix, region reasoning and the short-prompt trap: [regions](/docs/model-selection/regions).

Sol is also the worst GPT variant on **quality** in the cross-family study — 0 of 4 agents
graded "as good", and the only cell that escalated both anti-false-positive fixtures.
[Cross-family study](/docs/model-selection/cross-family-study#gpt-56-sol-is-the-worst-variant-on-quality-at-4x-lunas-price).

## Why the specialists did not follow

The obvious next question after moving the synthesizer is whether to move the eight agents. It
was measured — 120 blind-judged analyses, two judges, $16.8869 — and the answer is **not yet**.

| | Synthesizer | Specialists |
|---|---|---|
| What the model produces | A **21-key JSON object** whose shape is machine-validated on every call | **Titled prose** that a human underwriter reads, whose quality is the product |
| How correctness is checked | Contract validation: 42/42, deterministic | Band agreement, anti-FP escalation, `_context` grounding, output contract |
| Prompt size | 31,343 chars | ~7,500 chars |
| Measured decision | GPT, on latency | **Claude, on `_context` grounding: 0.642 vs 0.357, lower on 4 of 4 agents** |

The asymmetry is the point. **The synthesizer's output contract is checkable by a machine on
every single call, so a latency win can be taken without a quality argument.** A specialist's
output is a fraud judgement, and its quality axis — validating each signal against its paired
`_context` evidence, as every specialist prompt requires — is measurably weaker on GPT.

<Callout type="info" title="The specialist question is not closed, and the plumbing is not the blocker">
`agents/fanout.py` routes a GPT specialist today
(`transport_for('openai.gpt-5.6-luna') == 'bedrock-mantle'`), so reversing the decision is one
value in `SPECIALIST_MODELS`. The hold is a measurement result. One prompt-engineering
experiment on grounding is what stands between it and a projected **47.8%** specialist cost
reduction. [Cross-family study](/docs/model-selection/cross-family-study#what-would-change-the-answer).
</Callout>

## What is unproven about the synthesizer

<Callout type="error" title="Luna's fraud reasoning has never been blind-judged against a Claude synthesizer">
This is the gap, stated as `TIER_RATIONALE` states it: *"WHAT IS UNPROVEN: that Luna's fraud
REASONING matches Sonnet 5's. The 42 runs validated 21 keys every time and the verdict-stability
check found 12 of 14 applications stable, but no blind judge has scored Luna against a Claude
synthesizer across the fixture set."*

What exists instead:

- **42 runs, 21 keys every time, 0 repairs** — a *contract* result, not a reasoning one.
- **12 of 14 applications verdict-stable** across three repetitions of byte-identical input.
  APP-1005 and APP-1012 moved between HIGH RISK and MEDIUM RISK.
- **24 matrix calls unanimous on HIGH RISK / DECLINE** across three variants and three regions
  — a *determinism* observation, not an accuracy one.
- **Mild corroboration** from the specialist cross-family study that Luna reasons acceptably on
  this customer's fraud material — but that is not a synthesizer result: the synthesis prompt is
  31,343 characters against a specialist's ~7,500, and it emits a 21-key object rather than
  prose.

The eval that would close it is the calibration judge in
`evals/evaluators/pp_calibration_judge.json`, run across the fixture set on both a Luna and a
Claude synthesizer.
</Callout>

Also unproven: **that the variant or region ranking holds for any other prompt size.** It is a
property of a ~31K-character prompt with an ~800–1000 token reply, and a short-prompt probe
ranks the regions differently.

## Reversing it is one environment variable

```bash
BEDROCK_MODEL_SYNTHESIZER=global.anthropic.claude-sonnet-5
```

`agents/synthesize.py` routes on the **model id**, not on a flag: `agents.mantle.is_mantle_model`
returns True for anything starting `openai.gpt-5`, and anything else goes through
`build_bedrock_model` and Converse. So there is no second code path to maintain and no feature
flag to get wrong — the same bounded-repair loop and the same `Adjudication` validation apply to
both families.

## Operational notes on the mantle path

Verified live, and each one cost time:

<Steps>

<Step>

**GPT-5.x is not on Bedrock Converse or InvokeModel.** `BedrockModel` rejects the id with
`ValidationException: The provided model identifier is invalid`.

</Step>

<Step>

**The hostname is `bedrock-mantle.{region}.api.aws`, not `.amazonaws.com`.** The
`amazonaws.com` form does not resolve at all (NXDOMAIN), which looks exactly like a permissions
problem and is not one.

</Step>

<Step>

**The path is `/openai/v1`, not `/v1`, and the two are mutually exclusive.** The Strands
documentation shows `/v1` with `openai.gpt-oss-120b`, which is correct for that pair and
**wrong for GPT-5.6**. [Detail](/docs/platform/bedrock-mantle).

</Step>

<Step>

**Auth is a bearer token** from `aws_bedrock_token_generator.provide_token`, not SigV4 request
signing. Tokens are short-lived, so one is minted per call rather than cached across a
long-running runtime. IAM needs `bedrock-mantle:CreateInference` (AWS managed policy
`AmazonBedrockMantleInferenceAccess`) — a different action prefix from both `bedrock:` and
`bedrock-agentcore:`.

</Step>

<Step>

**These are reasoning models.** `temperature` / `top_p` / `top_k` are ignored; use
`reasoning={"effort": ...}`. Measured on the synthesis prompt, both `low` and `medium` returned
a valid 21-key object; `low` is the default because the master prompt is an explicit
instruction set, not a puzzle.

</Step>

<Step>

**No `global.*` or `us.*` prefix and no cross-region inference.** The id is bare
(`openai.gpt-5.6-luna`) and the call is in-region only — which is why the region is chosen from
a measurement rather than from `AWS_REGION`.

</Step>

<Step>

**Regional availability differs per variant.** Luna and Terra: us-east-1, us-east-2, us-west-2.
Sol: us-east-1 and us-east-2 only.

</Step>

</Steps>
