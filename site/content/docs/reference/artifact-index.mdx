*For anyone who wants to check a number on this site rather than take it.*

Four measurement artifacts, **$28.89** of measured spend between them, each committed with its own
recorded timestamp, region and git SHA taken from its `run` block rather than from a commit log.
Every figure on this site traces to one of these files; this page is the other direction, so a reader
can ask what a given artifact does and does not support.

## Four measurement artifacts

| Artifact | What it is | Recorded run | Measured spend |
|---|---|---|---:|
| `evals/results/pipeline_14x3_us-east-1.json` | 14 fixtures × 3 repetitions = **42 adjudications**, **336 specialist calls**, 41 complete + 1 degraded | 2026-07-28 07:42 UTC, `us-east-1`, git `9bb569b` | **$6.4659** |
| `evals/results/tier_quality.json` | Claude-only tier study, **48 blind-judged analyses**, judge Claude Opus 5, candidates Haiku 4.5 / Sonnet 5 / Opus 5 | 2026-07-28 17:29 UTC, `us-east-1` | **$4.9088** |
| `evals/results/set_comparison.json` | Cross-family study, **120 analyses / 240 verdicts**, two judges biased in opposite directions | 2026-07-28 21:32 UTC | **$16.8869** |
| `evals/results/tail_analysis.json` | Re-analysis of the pipeline run's tail, plus one live cap sweep of 30 calls. Its `source` block names the pipeline artifact it reads | derived from the 07:42 run | **$0.6278** (the cap sweep only) |

<Callout type="warn" title="Note the two different clocks: the benchmark measures the PREVIOUS assignment">
The pipeline benchmark ran at **07:42 UTC**; the two quality studies ran at **17:29** and **21:32** the
same day. Model assignment changed *between* them — `synthetic` and `rings` moved off Opus 5 after the
benchmark. So the benchmark measures the previous assignment, and the
[assignment page](/docs/model-selection/assignment) marks the current one's end-to-end cost as a
projection for exactly that reason.
</Callout>

Each JSON has a companion `.md` written for a human: `pipeline_14x3_us-east-1.md`, `tier_quality.md`,
`set_comparison.md`, `tail_analysis.md`. The Markdown is generated from the JSON, so if the two ever
disagree **the JSON is authoritative**.

## Sidecars, and why reuse is recorded

`set_comparison_analyses.json` and `set_comparison_verdicts.json` hold the raw analyses and raw
verdicts behind the summary; `tier_quality_analyses.json` and `tier_quality_verdicts.json` do the same
for the tier study.

They exist because both studies **reuse** earlier work instead of re-billing for it, and that has to be
visible or a spend figure becomes uncheckable. Both artifacts record it explicitly in `live_calls`.

| Artifact | `specialist_calls_made` | Verdicts reused | Analyses reused | Spend still reported |
|---|---:|---:|---:|---:|
| `set_comparison.json` | **0** | 240 | 120 | $16.8869 |
| `tier_quality.json` | **0** | 48 | 48 | $4.9088 |

`tier_quality.json` additionally names its `reuse_sources` — three earlier sweeps, `tiering.json`,
`tq_bustout_identity.json` and `tq_rings_synth_extra.json`. Both `spend_actual_usd` blocks carry the
same note: rows reused from an earlier sweep carry that sweep's measured cost, and **rows with no
recorded usage contribute nothing rather than an estimate**. That is why the spend figures are exact
rather than round.

## Deliberately absent

<Callout type="error" title="Three things you will not find, and should not infer">
- **No end-to-end measurement of the current assignment.** The 42-run benchmark predates the
  `synthetic`/`rings` move to Sonnet 5. Re-running it is one command and it has not been run.
- **No AgentCore Runtime overhead figure.** The benchmarked calls left the benchmark host directly for
  Bedrock, so Runtime, cold start and SSE framing all sit outside the timed window.
- **No throughput or concurrency figure.** Every measurement ran **one application at a time**. Nothing
  here says what happens when adjudications overlap.

Each is stated on the page that would otherwise be read as covering it, not only here.
</Callout>

## Reproducing any of it

```bash
# offline: 1,238 tests collected, no AWS calls
MOCK_MODE=1 python3 -m pytest tests/ -q

# the pipeline benchmark (real Bedrock spend)
AGENTCORE_BENCH_ALLOW_LIVE=1 python -m evals.bench --pipeline --repetitions 3
```

The live gate is `AGENTCORE_BENCH_ALLOW_LIVE=1`, and it exists so a spend-incurring run cannot be
started by muscle memory. See [Eval harness](/docs/reference/eval-harness) for each harness's own gate
and what it measures.

## Still unknown

**No artifact here was produced from a deployed AgentCore Runtime.** All four record `run.host` as a
developer machine calling Bedrock and bedrock-mantle directly. Anything a reader wants to know about
Runtime behaviour — cold start, SSE framing, session handling under load — is not in these files and
is not estimated in them.
