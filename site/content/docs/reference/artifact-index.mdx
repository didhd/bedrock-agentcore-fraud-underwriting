For anyone who wants to check a number on this site rather than take it. Each artifact below

This site's rule is that every figure traces to a file. This page is the other half of that
rule: the list of files, so a reader can go the other direction and ask what a given artifact
does and does not support.

## The four measurement artifacts

<Callout type="warn" title="Note the two different clocks">
The pipeline benchmark ran at **07:42 UTC**; the two quality studies ran at **17:29** and
**21:32** the same day. The model assignment changed *between* them — `synthetic` and `rings`
moved off Opus 5 after the benchmark. So the benchmark measures the **previous** assignment,
and the [assignment page](/docs/model-selection/assignment) marks the current one's
end-to-end cost as a projection for exactly that reason.
</Callout>

| Artifact | What it is | Recorded run | Measured spend |
|---|---|---|---:|
| `evals/results/pipeline_14x3_us-east-1.json` | 14 fixtures × 3 repetitions = **42 adjudications**, **336 specialist calls**, 41 complete + 1 degraded | 2026-07-28 07:42 UTC, `us-east-1`, git `9bb569b` | **$6.4659** |
| `evals/results/tier_quality.json` | Claude-only tier study, **48 blind-judged analyses**, judge Claude Opus 5, candidates Haiku 4.5 / Sonnet 5 / Opus 5 | 2026-07-28 17:29 UTC, `us-east-1` | **$4.9088** |
| `evals/results/set_comparison.json` | Cross-family study, **120 analyses / 240 verdicts**, two judges biased in opposite directions | 2026-07-28 21:32 UTC | **$16.8869** |
| `evals/results/tail_analysis.json` | Re-analysis of the pipeline run's tail. **Derives no new calls** — its `source` block names the pipeline artifact it reads | derived from the 07:42 run | **$0** (no live calls) |

Each JSON has a companion `.md` written for a human: `pipeline_14x3_us-east-1.md`,
`tier_quality.md`, `set_comparison.md`, `tail_analysis.md`. The Markdown is generated from the
JSON, so if the two ever disagree **the JSON is authoritative**.

### The sidecars, and why reuse is recorded

`set_comparison_analyses.json` and `set_comparison_verdicts.json` hold the raw analyses and
raw verdicts behind the summary; `tier_quality_analyses.json` and `tier_quality_verdicts.json`
do the same for the tier study.

They exist because both studies **reuse** earlier work instead of re-billing for it, and that
has to be visible or a spend figure becomes uncheckable. Both artifacts record it explicitly
in `live_calls`:

- `set_comparison.json` — `reused_analyses: 120`, `judge_verdicts_reused_from_cache: 240`,
  `specialist_calls_made: 0`. Every row came from the sidecars; the `$16.8869` is the spend
  those calls **originally** cost, carried forward.
- `tier_quality.json` — `reused_analyses: 48`, and `reuse_sources` naming the three earlier
  sweeps (`tiering.json`, `tq_bustout_identity.json`, `tq_rings_synth_extra.json`).

Both `spend_actual_usd` blocks carry the same note: rows reused from an earlier sweep carry
that sweep's measured cost, and **rows with no recorded usage contribute nothing rather than an
estimate**. That is why the spend is exact rather than round.

## What is deliberately absent

<Callout type="error" title="Three things you will not find, and should not infer">
- **No end-to-end measurement of the current assignment.** The 42-run benchmark predates the
  `synthetic`/`rings` move to Sonnet 5. Re-running it is one command and it has not been run.
- **No AgentCore Runtime overhead figure.** The benchmarked calls left the benchmark host
  directly for Bedrock. Runtime, cold start and SSE framing are all outside the timed window.
- **No throughput or concurrency figure.** Every measurement ran **one application at a time**.
  Nothing here says what happens when adjudications overlap.

Each is stated on the page that would otherwise be read as covering it, not only here.
</Callout>

## Reproducing any of it

```bash
# offline: 1224 tests, no AWS calls
MOCK_MODE=1 python3 -m pytest tests/ -q

# the pipeline benchmark (real Bedrock spend)
AGENTCORE_BENCH_ALLOW_LIVE=1 python -m evals.bench --pipeline --repetitions 3
```

The live gate is `AGENTCORE_BENCH_ALLOW_LIVE=1`, and it exists so a spend-incurring run cannot
be started by muscle memory. See [the eval harness](/docs/reference/eval-harness) for each
harness's own gate and what it measures.
